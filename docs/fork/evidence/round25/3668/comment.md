I've pushed a focused fix for the Magpie-side account badge fallback in [3e6f4077577d0af80890a542a3fb0d08f8249260](https://github.com/skygunner/magpie/commit/3e6f4077577d0af80890a542a3fb0d08f8249260), on [`fix/r25-grok-plan-absent-label`](https://github.com/skygunner/magpie/tree/fix/r25-grok-plan-absent-label).

When a Grok account has no reported plan, its badge now names the provider, **Grok**, instead of inventing a **SuperGrok** tier. Known plans, including `SuperGrok Heavy`, are preserved verbatim. This applies to plugin-backed Grok accounts too; other agents keep their existing labels.

The new regression exercises the actual Providers page's account pills. On a clean archive of base `19253f67bca2310c32739a6eaac88546b3574dbc` with only that test added, it fails with `absent Grok plan names the provider, no invented tier`: actual `['SuperGrok', 'SuperGrok']`, expected `['Grok', 'Grok']`. With the fix, the related GUI and translation tests pass (9/9), using Chromium and WebKit and covering English, Simplified/Traditional Chinese, Japanese and German, and the whole `./internal/gui` Go package passes under `-race -shuffle=on` (the same run red-lines the core script budget on the initial variant, which added bytes to `app.js`). `node --check`, `gofmt -l`, `go vet ./...`, the native build, Linux amd64 `nogui` build and Windows amd64 build also pass with Go 1.26.8.

This is only the missing-plan badge portion of #3668. The provider title branding and reporting the actual signed-in plan still require a change in the community Grok plugin. That repository is untouched here, and this does not claim to resolve the whole issue. No live Grok account was tested.
