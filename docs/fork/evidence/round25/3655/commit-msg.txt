gateway: a write_stdin wait on a running process is not a tool loop (hibaliqya-yonma, #3655)

Codex Desktop's write_stdin with empty chars, polling a session that has no
output yet, produced eight exchanges whose results steadyResult makes
identical (only Chunk ID and wall time move). stoppedToolLoop read them as
the same call answered the same way and ended the turn with "magpie stopped
this turn", while the process was still working and produced its result
later.

exchangeOf now marks a turn whose every call is such a wait: the name
write_stdin, empty chars, a numeric session_id, and a result line saying
"Process running with session ID <the same id>". A conversation ending in
one is no loop (toolLoopOf). Non-empty chars, a result that names no
running session or another one, and an unreadable session_id still count the
turn as work, so repeated reads and a finished or mistyped handle stop as
before.
